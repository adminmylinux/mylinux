## Fix these first

In order of harm, across all areas. Each is described in its area section below.

1. **The guest can write, read and delete files on the Mac through symlinks in the share folder** (host H1).
   A compromised guest, or anything running as root in it, can overwrite `~/.zshrc` on the Mac.
2. **An Omarchy machine can be started twice on the same disk** (Mac H1). The launcher never recognises a running
   Omarchy machine it did not start, so the disk can be corrupted.
3. **A pinned VNC host can be downgraded to no encryption** (Mac H3). A network attacker offers only VNC password
   authentication and the launcher connects without a warning.
4. **Settings wipes the VNC and SSH passwords the viewer saved** (shell H1).
5. **An interrupted first-time setup can be marked finished and never retried** (image H1).
6. **Chromium runs as root without its sandbox**, next to secrets and the share (image H2; known roadmap item).
7. **The Omarchy Session menu cannot work in the installed app**, and a quote in the share path runs shell
   commands on the Mac (host H2, Mac H2).
8. **The launcher does not start on a Mac without Homebrew's libvncserver** (Mac M3).
9. **The Settings panel cannot be reopened after Esc** and leaves keyboard focus broken (shell H2).
10. **The first-run dialog returns after setup finishes and autostart does not run** (shell H3).

## Guest shell and compositor (shell/)

### High

- **H1. Settings wipes the viewer's passwords.** checked. `shell/secrets.cpp:9,64-80`, `shell/vncview/machines.cpp:97`.
  `Secrets` reads `secrets.env` once at start and writes its in-memory copy back on every change. vncview writes
  `VNC_<NAME>_PASSWORD` into the same file from its own process. Saving any API key afterwards deletes the machine
  passwords; hand edits made while the shell runs are lost the same way. Fix: re-read the file inside `set()`
  before changing it, and share one parser and writer between both programs.
- **H2. Esc in the Settings panel breaks its visibility binding.** checked. `shell/SettingsPanel.qml:56`,
  `shell/Desktop.qml:196,412,417`. `panel.visible = false` replaces the binding `visible: menuBar.settingsOpen`.
  The gear stays highlighted, an invisible click catcher eats the next click, the panel cannot be opened again, and
  `panelHasKeys` stays true so every later focus change hands the keys to a hidden text field. Fix: close through
  the owner (`menuBar.settingsOpen = false`).
- **H3. The first-run dialog comes back after setup, and autostart never runs.** checked. `shell/FirstRun.qml:16,32`.
  `ready` is a binding on `Launcher.fileExists(...)`, which notifies nothing, so it is evaluated once. The timer's
  "became ready" test can never fire. Fix: make `ready` a plain property set in `readStatus()`, and make
  `runAutostart` skip what it already started.

### Medium

- **M1. Any bar-module update rebuilds every module.** `MenuBar.qml:172-186`, `barmodules.cpp:128-137`. The
  Repeater's model is replaced on each update, so every delegate, including QML modules, is destroyed and created
  again. With the shipped examples, the agents module refreshes its usage scan about every 10 s instead of every
  5 min and tooltips vanish under the pointer. Fix: a list model keyed by module id with per-row updates.
- **M2. Closing a VNC tab that is still connecting freezes the viewer for 6 s, then terminates the thread.**
  `vncview/vncsession.cpp:151-169,209-217`. Fix: set libvncclient's connect and read timeouts, `shutdown()` the
  socket in `close()`, and never call `QThread::terminate()`.
- **M3. Saved VNC and SSH passwords are exported to every terminal, agent and bar module.** `machines.cpp:97`
  with `board/overlay/usr/lib/mylinux/secrets.sh`. They are ordinary lines in `secrets.env`, so the export filter
  passes them; `env` inside Claude Code shows them. Fix: keep viewer credentials in their own 0600 file, or skip
  `*_PASSWORD` keys in the export.
- **M4. Theme colours are not validated before they reach running terminals.** `themestore.cpp:34-38,149-155`,
  `launcher.cpp:84-91`. Any value starting with `#` is accepted and written into OSC escape sequences. A downloaded
  theme can inject escape sequences into foot (for example setting the clipboard). Fix: accept only
  `#RRGGBB` or `#RRGGBBAA`.
- **M5. The ⌘-drag layer stays active during a VNC input grab.** `MacWindow.qml:381-385`. Super+click never reaches
  the remote. Fix: disable it while the output is grabbed.
- **M6. Resizing a tiled window by its edge snaps back at the next focus change.** `MacWindow.qml:98,406-437`.
  Fix: turn the drag into a tiling ratio change, or float the window first.
- **M7. Codex token counts include cached input twice.** `agentusage.cpp:171`; the wrong total is locked into the
  vmtest fixture (`vmtest.py:792`). Fix: use `total_tokens`, or input plus output.
- **M8. Restart and Shut Down run at once, without confirmation.** `MenuBar.qml:30,68-69`, `Spotlight.qml:120-122`,
  `Desktop.qml:239-240`. The menu items carry an ellipsis but act immediately; "Restart the desktop" is the
  preselected first row of the System menu and closes every app. Fix: a small confirm sheet.

### Low

- Settings' "✓ set" markers and field values never refresh, because `Secrets.has()` and `get()` are invokables
  (`SettingsPanel.qml:48,53`).
- Keys can stay pressed on a VNC remote: the release keysym is recomputed from the current modifier state
  (`vncsurface.cpp:157-174`).
- Retrying a "connect once" tab loses its username and password; a one-off tab named like a saved machine picks up
  that machine's password (`vncview/Main.qml:162-165`).
- Framebuffer size and counters are read across threads without the lock (`vncsession.h:44-45`).
- SSH terminal: paste is not bracketed, Ctrl+[ ] \ and Ctrl+Space are dropped, there is no selection or copy
  (`termsurface.cpp:126-131,163-168`).
- SSH launch: the tmux name is pasted into the remote command unquoted, a host starting with `-` is read as an ssh
  option (no `--`), exits are reported as 0 when the child is not yet reaped (`sshsession.cpp`).
- Server-controlled text (certificate name, error text) is rendered as rich text (`vncview/Main.qml:140-161`); set
  `textFormat: Text.PlainText`.
- The keybinding sheet closes on a bare `k`, so a search starting with k is impossible (`KeyHelp.qml:30`).
- A menu bar workspace click does not update "former workspace" (`MenuBar.qml:135`).
- Overlapping weather lookups: a stale reply can win (`weather.cpp:41-63`).
- `Launcher::writeFile` deletes the target before renaming and ignores write errors (`launcher.cpp:122-129`).
- Qt Wayland patch edges: a keyboard bound after focus never gets `enter`; data offers are created at version 3
  regardless of what the client bound; `0002` is hand-made and cannot be regenerated.

## Mac launcher (mac/)

### High

- **H1. Omarchy machines are never detected as running.** checked. `Runner.swift:325-332`, `run-omarchy.sh:146`.
  `diskInUse` looks for `file=<disk>,if=none`; `run-omarchy.sh` writes `if=none,id=root,file=<disk>,...`. After a
  launcher restart a running Omarchy machine shows as stopped, Start runs a second QEMU on the same raw disk, and
  Force Quit does nothing. Fix: pass `-pidfile` from both scripts and check the pid; add a `DRYRUN` test that
  matches both scripts.
- **H2. The Omarchy Session menu is broken in the installed app.** checked. See host H2.
- **H3. A pinned VNC host can be downgraded.** checked. `Remote/VncConnection.swift:123-124`. The client offers
  VeNCrypt, VNC password, none and ARD; the certificate pin is only checked on the X509 path. An attacker offering
  only type 2 gets a crackable challenge and a cleartext session; type 1 connects to the attacker's desktop. Fix:
  once a host is pinned, offer only VeNCrypt with X509 subtypes; otherwise warn before an unencrypted connection.

### Medium

- **M1. A hostile `machines.json` can run a command on the Mac through ssh options.** `Remote/SshTerminal.swift:45-50`,
  `Remote/RemoteSession.swift:69-84`. The host goes to ssh without `--`, and import reads a file from the
  guest-writable share. `host: "-oProxyCommand=..."` runs on the Mac. Fix: `--` before the destination, reject
  hosts and usernames that start with `-` or contain whitespace.
- **M2. Any process of the user can read every saved remote password without a prompt.** `RemoteProfile.swift:78-86`.
  Every item trusts `/usr/bin/security`, and the password passes on `security`'s command line. Fix: let the signed
  launcher binary be the askpass helper, and store items through the Security framework.
- **M3. The launcher needs Homebrew's libvncserver to start at all.** checked with `otool -L`. `Package.swift:14-15`,
  `build-app.sh`. Fix: bundle libvncclient and its OpenSSL in `Contents/Frameworks`, or weak-link it and disable VNC
  when it is missing.
- **M4. The full keyboard grab stays on without a working connection.** `RemoteWindow.swift:135-136,177-182`.
  After a failed connection every key, ⌘Q and ⌘Tab included, is swallowed and queued to a dead connection. Fix:
  grab only while connected, release on failure or close.
- **M5. Clicking "Connecting…" starts a second connection and never stops the first.** `RemoteWindow.swift:64-73`.
- **M6. A profiles file that fails to decode is overwritten with a default.** `Profile.swift:128-137`,
  `RemoteProfile.swift:100-104`. One unknown enum value empties the remote list; `lastError` is never shown. Fix:
  move a bad file aside, decode per item and tolerantly, show the error.
- **M7. An open remote window writes an old copy of its profile back** on a toolbar change, reverting edits made
  in the editor meanwhile (`RemoteWindow.swift:14,106,222`).
- **M8. A wrong saved VNC password retries forever**; an empty-password decision is remembered per host until the
  app quits (`RemoteWindow.swift:9,80-81`).
- **M9. Switching between two grabbing tabs breaks the grab**: `KeyboardGrab.start()` calls `stop()` instead of
  telling the previous owner (`KeyboardGrab.swift:29`, `VncView.swift:169-170`).
- **M10. "Replace and connect" is the default button on the changed-certificate sheet** (`RemoteWindow.swift:145-151`).
  One Return accepts a possible man-in-the-middle. Make Cancel the default.
- **M11. Keys stay pressed on the remote when the window loses focus** (`VncView.swift:147-163`).
- **M12. The VNC surface, width and height are shared between threads without a lock**; the old surface is locked
  and the new one unlocked on a resize (`VncConnection.swift:62-71,87-91,139-141`).

### Low

- The askpass helper returns the saved password for every prompt, including key passphrases and one-time codes
  (`SshTerminal.swift:35,58`).
- Closing an SSH window leaves an unreaped ssh process (`RemoteWindow.swift:184-188`).
- A restored remote window that crashes the app crashes it again at every launch (`RemoteSession.swift`); rename
  the session file while restoring.
- `refreshExternal` runs `pgrep` synchronously on the main thread every 4 s per profile (`Runner.swift:240-249,360-374`).
  While a keyboard grab is on, every key on the Mac waits for this thread.
- Closing the last window during the 1.4 GB Omarchy download quits the app; Cancel does not stop curl
  (`App.swift:67-69`, `ImageManager.swift:58`).
- The Dock and ⌘K bring the first `dev.mylinux.vm` app forward; Omarchy is `dev.mylinux.vm.omarchy`, and with two
  machines it can be the wrong one (`App.swift:123`).
- Clipboard items marked concealed by password managers are sent to the remote on every focus (`RemoteWindow.swift:180`).
- The certificate fetch has no timeout (`CertPin.swift:43-99`); console sockets are in the shared `/tmp`
  (`Runner.swift:34-37`).
- Test hooks ship in the product (`MYLINUX_TEST_TYPE`, the event trace, stderr state logs); put them behind
  `#if DEBUG`.
- `TLSPeek` uses deprecated SecureTransport, which stops at TLS 1.2, so a TLS-1.3-only server cannot be pinned.
- Swift 5 language mode hides the concurrency checks that would catch M12 and the runner races.
- `mac/spike/` is superseded by `Remote/` and can be deleted; history keeps it (commit `0583e30`).

## Host scripts, QEMU runtime and Omarchy session (run*.sh, tools/, omarchy/)

### High

- **H1. The guest can reach Mac files through symlinks in the share.** checked. `tools/clipboard-host.sh:13-33`,
  `run.sh:136,184`, `run-omarchy.sh:118`. The share uses `security_model=none`, so a symlink the guest makes is a
  real symlink on the Mac, and the Mac-side scripts follow it:
  - `printf '%s\n' "$S" > "$GS.done"` writes guest-chosen text wherever `guest.seq.done` points, for example
    `~/.zshrc`;
  - `cp -f "$G" "$M.last"` copies whatever `guest.txt` points at (say `~/.ssh/id_ed25519`) into the share;
  - `rm -f "$SHARE_DIR/clipboard"/*.txt` deletes `.txt` files in whatever folder `clipboard` points at;
  - the Omarchy start copies `omarchy/session/*` through planted links.

  Fix: keep the Mac-side state files outside the share, open guest-facing files with `O_NOFOLLOW`, refuse to work
  when `clipboard` or `mylinux-tools` is a symlink. Longer term, move the myLinux clipboard to a virtio-serial port
  as the Omarchy path already does. No test puts a symlink into the share today.
- **H2. The Session menu fails in the installed app, and a quote in the share path runs commands on the Mac.**
  checked. `run-omarchy.sh:120`, `qemu-cocoa-size-buttons.patch:253-262`. The command is
  `$REPO/tools/omarchy-session-mac.sh '$SHARE_DIR'`, run with `/bin/sh -c`. In the installed app `$REPO` contains
  "myLinux Launcher.app", so the space splits it and every click fails silently. A share named `x'$(cmd)'` runs
  `cmd`. The patch also reads the string in the system encoding, so non-ASCII paths break. Fix: two environment
  variables and an `NSTask` argument array built from UTF-8.
- **H3. Saving at logout wipes the saved Omarchy session.** checked. `omarchy/session/omarchy-session:56-69,91-96`,
  `omarchy-session-restore.service:12`. When `hyprctl` fails, `snapshot()` returns zero windows and `save()`
  replaces `session.json` with it. At logout Hyprland is usually gone before `ExecStop` runs, so the next login
  restores nothing. (The stop order was not observed in a VM; if Hyprland is still alive then, a partial snapshot
  is still possible.) Fix: refuse to save an empty or failed snapshot and keep the previous file.

### Medium

- **M1. The full screen hooks in the Cocoa patch apply to every window and quietly switch on Zoom To Fit.**
  Patch lines 54-83, 343-352. After one trip through full screen a myLinux window loses its one-pixel-per-point
  behaviour, and the Zoom To Fit menu item gets out of step. Fix: gate the hooks, restore the resizable bit,
  update the menu item.
- **M2. Apps with several windows in one process are saved and restored wrongly by the Omarchy session agent**
  (`omarchy-session:32-42,64,78-89`): all Chromium web apps share one pid and one command line. Collapse windows per
  pid and rebuild web-app commands from the window class.
- **M3. Clipboard privacy.** Both bridges copy concealed password-manager items to the guest, and the myLinux one
  writes them to `share/clipboard/mac.txt`. The guest can replace the Mac clipboard at any time, even unfocused
  (`clipboard-host.sh:30-33`, `omarchy-clipboard.py:31-45,98-102`).
- **M4. `python3` on the Mac is a hidden dependency.** `run.sh:60-61`, `run-omarchy.sh:131,176`,
  `make-app-bundle.sh:36`. Without Command Line Tools it is a stub; `run.sh` then silently fails to create the apps
  disk (the failure sits in an `&&` list that `set -e` ignores), and `run-omarchy.sh` leaves a multi-GB `.new` file.
- **M5. The runtime and image downloads trust a checksum from the same release as the file.**
  `get-qemu-runtime.sh:29-43`, `get-image.sh:23-27`. The runtime then gets its quarantine flag removed and runs with
  the hypervisor entitlement. `get-omarchy.sh` does it right with a pinned hash; do the same here.

### Low

- The exit trap can kill an unrelated process that reused the placer's pid hours later (`run.sh:183-184`).
- The cleanup misses `guest.seq.done`, so the first guest copy of a new session can be ignored (`run.sh:136,184`).
- A comma in a machine name or path breaks QEMU's option parsing (`run.sh:110-119`, `run-omarchy.sh:144-146`);
  escape it as `,,`.
- Two machines starting at once rewrite the shared app bundle at the same time (`make-app-bundle.sh:35-80`).
- Two first starts of one Omarchy machine unpack into the same `.new` file; nothing removes it after a failure.
- Cocoa patch: the full screen box shows on every Space; `sessionStatus` reads a guest-written file on the main
  thread (a FIFO freezes QEMU's UI); objects are never released in this manual-refcount code.
- Omarchy session: "Off" only stops the timer until the next login; a bad interval value crashes the agent.
- Sockets with predictable names in `/tmp` (`run-omarchy.sh:95`); use the per-user temp folder.
- About 40 lines are duplicated between `run.sh` and `run-omarchy.sh` and have drifted (display choice, `RES`
  clamping, the share-folder guard); `share/instance` is written but never read.

## Image and guest init (board/, configs/, package/, build.sh)

### High

- **H1. An interrupted first-time setup can be marked finished.** checked. `apps-setup:72`, `S45apps:32-35`. The
  checks meant for disks from before the stage markers also match a new disk whose setup was cut off: a disk with
  `usr/bin/dpkg` counts as a finished Debian unpack, and one with `usr/bin/chromium` counts as fully set up. A power
  cut at the wrong moment leaves a broken chroot that is never repaired, or a desktop missing packages. The
  interruption test (`disktest.py:165-211`) resumes without a reboot, so it misses this. Fix: write a
  `setup-started` marker first, and apply the old-disk rules only when no marker exists.
- **H2. Chromium runs as root with `--no-sandbox`** (`usr/bin/chromium:3`, `apps-mounts:18,23`). The chroot shares
  `/dev`, `/proc`, `/sys`, `/tmp` and the share with the host, so one renderer exploit reaches `secrets.env`,
  `~/.ssh`, the Tailscale key and the Mac share. Fix: an unprivileged user for browsers; until then, say so in the
  README.

### Medium

- **M1. Every secret reaches every terminal and agent**, including the viewer's passwords and other providers' API
  keys; the `all` policy also covers apt and the Claude installer (`secrets.sh`, `apps-run:16-37`). Give each
  program its own key list.
- **M2. `apps-run` silently switches to `/root` from any folder outside `/root` and `/tmp`.** checked.
  `apps-run:9`. `cd /mnt/share/project && claude` runs Claude in `/root`, which is pre-trusted and holds the
  secrets. Keep any directory that exists in the chroot, or refuse.
- **M3. The apps disk is never checked with fsck** and is mounted without `errors=remount-ro` (`S45apps:28`), although
  closing the window is a power cut the code expects.
- **M4. The guest clock is never synced after boot.** No ntpd; after a night of Mac sleep, apt and TLS fail.
- **M5. Development overrides in the share are live in every installation.** checked. `S99shell:28-32`,
  `usr/bin/vnc:4`. Any executable `myshell` or `vncview` in the chosen share folder runs as root, and a `myapp`
  there puts the whole share first on `PATH`. Gate this on a developer flag.
- **M6. No upgrade path for existing apps disks.** `SETUP_VERSION` is written but never compared, so packages a new
  release adds never reach old disks.
- **M7. `build.sh` builds whatever `~/br/output` is configured for.** It never re-runs the defconfig, relies on the
  saved `BR2_EXTERNAL` (a build from a worktree uses the main checkout's sources), and does not check that
  `tools/buildroot-patch.sh` was applied.
- **M8. The chroot's DNS settings are copied once**, before Tailscale starts, so MagicDNS names never resolve for
  Debian programs (`apps-mounts:38`).

### Low

- tailscaled is stopped without waiting and never restarted if it dies (`S47tailscale:20-26`).
- The chroot mounts a new devpts instance instead of binding the host's, so `apps-run tty` and tmux from foot
  probably fail (`apps-mounts:33`; to confirm with `apps-run tty`).
- Files written to the RAM home before setup (API keys, GTK settings) disappear when the disk is bound over `/root`.
- The base system is fixed to Europe/Oslo while the chroot runs in UTC (`mylinux_defconfig:48`).
- Downloads have no connect or stall timeout and allow non-HTTPS redirects (`fetch.sh:11`).
- No firewall and no `--shields-up`: anything bound to 0.0.0.0 is reachable from the whole tailnet.
- The initramfs is 291 MiB uncompressed in RAM; the udev hwdb, a second Tailscale binary and unused Qt Quick
  Controls styles are easy savings.
- Build provenance records only this repository's revision, not Buildroot's.

## UI and UX

Screenshots were taken from the test VM at 2520×1368 (default share settings). All items were confirmed in code.

**Desktop shell.**

- **The keybinding sheet uses the ⌘ symbol for the Option key.** Its footnote explains "⌘ = Option key", but Mac
  users read ⌘ as Command, and the README tells them Option is Super. Show ⌥ (or "Super") in the default `opt` mode
  and ⌘ only under `GRAB=full`.
- **Long key combinations overlap their description in the keybinding sheet.** The description is placed at a fixed
  150 px (`KeyHelp.qml:106`) while the key cap grows with its text; "⌘ Space / ⌘ Esc / ⌘ D" runs into "Menu: type to
  find anything". Size the key column to its widest entry or elide.
- **The theme picker opens on the first theme, not the current one.** The current theme (Gruvbox, with its
  checkmark) sits halfway down while Catppuccin is highlighted, so Return switches theme by accident. Preselect the
  current theme.
- **The System menu preselects "Restart the desktop"**, which closes every app; Restart and Shut Down do not ask
  either (shell M8). Put the harmless entry first and confirm the destructive ones.
- **The menu bar's Edit menu and Help menu contain only disabled items.** Either wire Cut, Copy and Paste to the
  focused client (send the key combination) or remove the menus.
- **The product name is spelled two ways.** The menu bar and first-run dialog say "mylinux" ("About mylinux",
  "Welcome to mylinux"); the launcher menu, README and Mac app say "myLinux" (`MenuBar.qml:8`, `FirstRun.qml:34`).
- **Title bars stay light grey under dark themes.** With Gruvbox selected, every title bar is light while the
  terminals and web apps are dark. Follow the theme's background, or the light/dark mode, for the frame.
- **Launcher menu icons are mixed Unicode glyphs** (a dot for Learn, a slash for Trigger, a bar for System) with
  different weights and sizes. A small consistent icon set (the SVGs already used for the dock) would read better.
- **Secondary text is very small.** Menu subtitles and the theme picker's "Dark · 2 backgrounds" are roughly half
  the size of the titles; at 1x on a large display they are hard to read.
- **Several menu bar status items are cryptic** ("○ off", the grid and bar glyphs) until hovered. A short label on
  first use or clearer icons would help.
- **Fixed pixel sizes break at 0.5x and 2x**: menu widths, the title text against the traffic lights, resize
  zones, the tiling gap, the About box (which also hard-codes "Qt 6.11"). The Style menu offers only 1x, 1.5x and
  2x although 0.5x and 0.75x are supported.
- **The first-run dialog is not reachable again once dismissed**, and a finished setup shows it again (shell H3).
- The screenshot action grabs only the desktop background layer, not the menu bar and dock, and gives no feedback.

**Mac launcher.**

- The custom screen size field vanishes when cleared or when the value matches a preset (`MachineView.swift:136,251-254`).
- Memory and disk-size pickers show blank when the saved value is not in their list (a new Omarchy machine gets
  8 GB, but an 8 GB Mac offers only 2, 4 and 6).
- The remote window's keyboard menu has no checkmark for the current mode, "Grab keys" shows no on/off state, the
  keyboard menu appears for SSH where it does nothing, and zoom stays enabled while disconnected.
- SSH exit codes are shown raw ("status 65280" instead of 255).
- The serial console re-lays out an 80,000-character SwiftUI `Text` for every chunk; an `NSTextView` would stay
  fast.
- A new remote password is saved only when the editor disappears or on Connect, so ⌘Q loses it; there is no way to
  forget a saved password.
- Remote rows have no double-click to connect and no connected indicator; Quick Connect has no "no matches" state.
- Neither store's `lastError` is shown anywhere, so a failed save is silent.

## Tooling, tests and documentation

- **`tools/check.sh` always reports a failure**: its first step runs `cd web`, which no longer exists. checked.
- **`tools/check.sh` cannot fail on Swift tests**: the step pipes `swift test` into `grep | tail`, so the exit status
  is `tail`'s. checked. It also skips `run-omarchy.sh` and `omarchy/session/*` in the syntax step, uses a fixed
  `/tmp` file, and hard-codes `/Users/vikkjart` for the SDK.
- **VM screenshots do not work on the project's own QEMU runtime.** checked. The runtime is built without libpng
  (`screendump` returns "Enable PNG support with libpng"), and with the GPU display the dump is black anyway.
  `tools/qmp.py` prints the error and exits 0, so `vmtest.py`'s failure screenshots silently never appear. Fix:
  have `qmp.py` exit non-zero on a QMP error, and run the VM suite on Homebrew's QEMU (`MYLINUX_QEMU=brew`) or save
  PPM. Screenshots for this review were taken that way.
- **The VM suite tests whatever shell binary sits in the test share.** `out/fresh-share/myshell` overrides the image's
  shell (image M5), and nothing records or checks which binary ran. A stale copy there makes the suite test old
  code while it reports on the new image. Print the shell's build revision in `diag.json` and compare it.
- **The README is out of date in places**: it says the standalone launcher still needs Homebrew's QEMU (the
  runtime replaced that; it now needs Homebrew's libvncserver instead, Mac M3), its layout section leaves out
  `run-omarchy.sh`, `omarchy/`, `package/libvterm` and `tools/qemu-runtime-patches/`, and the checks section still
  mentions the web typecheck. `docs/screenshot.png` is from 8 September.
- **Missing tests** for the riskiest paths: symlinks in the share; the disk-in-use pattern against both scripts'
  `DRYRUN` output; an interrupted Debian unpack followed by a reboot; a corrupted apps disk; grab hand-over between
  two windows and across a failed connection; hostile ssh arguments; the askpass prompt filter; a corrupt
  `profiles.json`; two machines started at once.
- **Duplication worth removing**: the app catalogue in four QML files; `secrets.env` parsing in two C++ files; the
  two stores in the launcher; the shared half of the two run scripts.
